## What is not satisfied yet (18)

### handshake

- Status: not measured
- Needs: core basics
- Why: wire.rs sends serverInfo first with PROTOCOL_VERSION 1 and the three required capabilities, so this should pass; never measured against the suite.
- Asserts: serverInfo carries the protocol version and an honest capability list, and reaches the client before any reply to anything it sent, so feature detection happens before the first decision.

### create

- Status: NO
- Needs: pty
- Why: conn.rs sends `created` but no following `attached`, so a client learns the session exists without ever being told it is attached and gets no scrollback baseline.
- Asserts: a create spawns a session, the client learns its identity from `created`, and the immediately following `attached` has empty scrollback because there is nothing to replay yet.

### create-guards

- Status: NO
- Needs: pty
- Why: the unknown-provider error reads "unknown provider: x" (lowercase) and there is no is-a-directory guard on cwd, so a doomed spawn replaces the clear error.
- Asserts: a bad provider or a missing cwd is one `error` frame with no session, and a client with no viewport of its own may omit cols/rows and let the core pick the spawn grid.

### attach-scrollback

- Status: not measured
- Needs: pty
- Why: attach replays registry scrollback; the meta and status fields on `attached.session` are unverified.
- Asserts: a second connection attaching to a live session receives the bytes it missed in `attached.scrollback`, not just the live tail.

### input-ack

- Status: not measured
- Needs: inputAck, pty
- Why: input/inputAck with seq is implemented; ordering under load and the no-seq-no-ack rule are unverified.
- Asserts: every sequenced input is acked exactly once, in the order it was sent, and an input without a seq is never acked — which is what lets a client buffer unacked keystrokes and resend them after a reconnect.

### resize

- Status: NO
- Needs: resizeAck, pty
- Why: no grid arbitration: resizeAck always reports denied:false, so a second viewer silently fights the first for the pty grid.
- Asserts: a sequenced resize is always acked, and the ack distinguishes three outcomes a client must handle differently: applied (the grid reached the pty), denied (another client owns the shared grid, so retrying is futile), and neither (nothing to resize, so re-assert).

### screen-stream

- Status: not measured
- Needs: screen, pty
- Why: screen streaming exists (alacritty_terminal + screen.rs); reset-on-alt-flip, cursor visibility and stop-on-unsubscribe are unverified.
- Asserts: subscribeScreen replies with a full snapshot, then sends only changed rows, forces a full repaint whenever the geometry or the alt buffer flips, reports cursor visibility, and stops entirely on unsubscribe.

### activity-notify

- Status: NO
- Needs: pty
- Why: conn.rs derives notify as `state == Idle`, so a waiting_input prompt never notifies and a prompt that cleared itself notifies again. The Swift core notifies on the turn boundary AND on a prompt, and stays quiet when a prompt clears.
- Asserts: the core reports a session as busy, idle or waiting_input, and `notify` marks exactly the edges a human should be pinged on: a finished turn and a prompt that needs an answer, never entering busy and never a prompt that cleared itself.

### activity-changes

- Status: NO
- Needs: pty, git
- Why: no settle-edge change rollup: the activity frame carries no `changes`, so a remote client cannot badge "finished, N files changed".
- Asserts: the activity frame that ends a turn over a dirty git tree carries the whole-tree change rollup, so a remote client can badge "finished, N files changed" without its own git access.

### queue

- Status: NO
- Needs: queue, pty
- Why: no `queue` capability: subscribeQueue / queueMessage / dequeueMessage decode to Unknown and are ignored.
- Asserts: the queue is pushed as a complete ordered list on subscribe and after every change, is replaced wholesale rather than patched, and stops being pushed after unsubscribe.

### exit-codes

- Status: not measured
- Needs: pty
- Why: exit is emitted; the -1-on-signal convention and the attach-then-exit replay for a dead session are unverified.
- Asserts: a child's own exit status reaches the client verbatim, a killed session still reports an exit rather than going quiet, and attaching to a dead session replays its scrollback and then re-states the exit instead of leaving the client waiting.

### unresumable

- Status: NO
- Needs: pty
- Why: `reactivate` is decoded as `attach`, so reviving a dead session cannot report unresumable; and an unknown session id answers `unresumable` where the Swift core answers `error: Session not found`.
- Asserts: reactivating a dead session whose CLI conversation id was never captured is answered with `unresumable` and a human-readable reason, not an error and not a silent nothing.

### errors

- Status: NO
- Needs: screen
- Why: attach of an unknown session answers `unresumable` rather than `error`, and setSkipPermissions / subscribeScreen error texts do not exist yet.
- Asserts: an addressable failure gets one `error` frame naming its session, malformed JSON gets one sessionless `error` and does NOT close the connection, and an unrecognised message type is ignored entirely so a newer client cannot be killed by an older core.

### tracked-prs

- Status: NO
- Needs: trackedPrs, pty, git
- Why: no `trackedPrs` capability: the tracked-PR registry, its poll loop and its fan-out are not ported.
- Asserts: subscribing returns the whole watch list, tracking a PR spawns its driving session and pushes a replacement list, and untracking pushes the list back — always the complete set, replaced wholesale.

### editor-terminal

- Status: NO
- Needs: editor, terminal, resizeAck, pty
- Why: no `editor` / `terminal` capability: there are no ephemeral ptys, so openEditor / openTerminal are ignored.
- Asserts: an editor or shell pty is addressable over the same input/resize/kill/output messages as a session, and terminalReady echoes the client's requestId so a client with several pending opens can tell them apart.

### adopt-external

- Status: NO
- Needs: adoptExternal, pty
- Why: the capability list advertises `adoptExternal` but ClientMessage has no AdoptExternal variant, so the frame decodes to Unknown and is silently dropped. Advertising a capability the core does not implement is worse than omitting it: feature detection is exactly what clients trust.
- Asserts: a conversation started outside juancode can be adopted by its own CLI id, becomes an ordinary session at the age it really started, and adopting it twice is a no-op rather than a duplicate.

### dispatch-correlation

- Status: NO
- Needs: pty
- Why: create accepts dispatchId but activity frames hard-code dispatch_id: None, and there is no dispatch ledger, so a repeat dispatch is started twice instead of rejected.
- Asserts: a create carrying a dispatch id claims that id, stamps it on every activity broadcast for the session's whole life so lifecycle events route back to the caller, and rejects a second create for the same dispatch.

### skip-permissions

- Status: NO
- Needs: pty
- Why: setSkipPermissions is not decoded, so the permission mode of a live session cannot be changed.
- Asserts: changing a live session's permission mode restarts the CLI in place and re-attaches the client to the same session id with the new mode on its meta, so the client never has to re-find the session.
