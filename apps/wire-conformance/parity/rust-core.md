## What is not satisfied yet (1)

### global-pause

- Status: n/a
- Needs: globalPause, pty
- Why: core does not advertise the "globalPause" capability
- Asserts: a core that advertises `globalPause` lets a client that is not the desktop sleep every live agent at once and bring back exactly that set. `pauseAll` answers with a `pauseState` naming the sessions it slept - no reply of its own, the same shape `sleepSession` has, because the set IS the answer - and each of them then exits, so the RAM the pause was taken for actually comes back. What the set does NOT contain is the load-bearing half: a session that exited on its own before the pause is not in it and is not woken by the play, which is the same refusal `sleepSession` makes for a session with no live pty and for the same reason - a crashed row resurrected by a global play is indistinguishable from one somebody paused, and reviving it is the bug this whole ticket is about. A session already asleep when the pause lands is excluded by the identical rule (`targets` filters on liveness, not on the dormant flag), so it stays the user's own sleep rather than becoming this pause's to wake. `resumeAll` clears the set before it revives anything, so the state a client renders its button off stops saying "paused" the moment the play starts and a revival that fails leaves a clickable sleeping row rather than a pause that never lifts.
